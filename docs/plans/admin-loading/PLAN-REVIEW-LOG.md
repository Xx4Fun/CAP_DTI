### Host dispositions

- AL-001 ACCEPTED. Finding 2 now specifies a separate `adminApi.getDashboard()` for `/admin/overview?dashboard=1` under its own cache key; `getOverview()` and its `'overview'` key stay for the shell. Verification adds a concurrent shell plus dashboard test asserting both URLs are requested and each caller gets its own shape.
- AL-002 ACCEPTED. `recent_reports` now states the queue's rules explicitly: `whereNotIn('status', UNREVIEWABLE_STATUSES)`, `latest()`, `submitted_at ?? created_at`. Backend test covers a newer processing draft beside an eligible report and a null `submitted_at`.
- AL-003 ACCEPTED. Every dashboard section has rows / empty array / null-or-absent (unavailable) states; reports gains the unavailable state. Server computes each section inside `rescue()` and returns `null` on failure so sections stay isolated. Tests cover absent fields, null sections and legitimate empty arrays.
- AL-004 RESOLVED BY REMOVAL. The nginx preflight shortcut is dropped, so there is no second CORS implementation to keep in parity. Reason: measured on an already-open connection (5 runs each, 2026-10-10), Laravel preflight took 65 to 102 ms versus 62 to 102 ms for an nginx static file, so the shortcut would save nothing. The earlier 159 to 235 ms figure included the TLS handshake. Evidence table and finding 3 are corrected; the plan no longer claims PHP boot is a material cost for small requests.
- AL-005 ACCEPTED. Idle warm-up of all chunks is removed. Finding 7 now prefetches one module's chunk on sidebar `pointerenter` or keyboard `focus` only; nothing is fetched at startup. Verification adds a throttled fresh-cache check that time to dashboard content is not worse than baseline and that no module chunk is requested before intent.
- AL-006 ACCEPTED WITH A CORRECTION TO MY OWN PREMISE. Revision 1 said seeded keys "have been replaced in place before"; the source does not support that. The only writers are `CommodityImageStorage::store` (new random key) and `stores:import-photos`, which writes only when the key is absent and aborts on different bytes (`ImportStorePhotos.php:50-52,72`). Finding 4 now records an amendment to the Field Monitoring plan's Task 1: the thumbnail importer checks the stored original's SHA256 against `source_sha256` before publishing; a regression test pins the photo importer's conflict refusal; `docs/DECISIONS.md` states that public image keys are write-once and a replacement needs a new key or a regenerated manifest. No storage check is added to normal reads. Finding 5's rationale is corrected accordingly.

Other changes in revision 2, not prompted by a finding: build Step 3 now contains only the upload `CacheControl` option; "Checked and left alone" lists the rejected nginx shortcut and notes heavier list endpoints are measured in Step 0 before any change is proposed.
